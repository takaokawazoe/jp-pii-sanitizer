# transcript_filler_stress.txt の正解

## 何のためのサンプルか

**PII は 1 件も入っていない。** マスクされるべき語がゼロで、`えっと` が
一度もマスクされないことだけを見る（`eval.jsonl` の `type:"NEGATIVE"`）。

音声の文字起こしをそのまま貼ったときの最悪ケースを再現している:

- **句読点が無い**。ASR の出力は句読点を打たないことが多く、これがあると
  NER のスパンが語の境界を越えて伸びやすい。
- **フィラーの密度が高い**（`えっと` が 26 回）。
- **会社の話をしている**。NER は 250 字チャンクの文脈で判断するので、
  社名の話題が続くとフィラーまで ORGANIZATION に寄る。

## 捕まえたい退行

この 3 つが揃うと `えっと` が**後ろの語とくっついて 1 スパンになる**:

    えっと弊社 → ORGANIZATION
    えっと大手 → ORGANIZATION

`furigana::org_name_core` は会社マーカー（株式会社 等）があれば芯だけを取り出すが、
マーカーが無いスパンは**そのまま返していた**ので、フィラーごと候補になっていた。
今は先頭の感動詞だけを落とす（末尾や「非名詞ぜんぶ」に広げると
`曲淵テクノサービス㈱` の `㈱` や `簓田` の `田` まで削れる。実測済み）。

`step2` 側の「名詞ゼロの候補を捨てる」門は、素の `えっと` 単独には効くが
`えっと弊社` には効かない（弊社が名詞なので）。**両方要る。**

## 残っている誤検知（既知・別件）

`弊社` と `大手` は今も ORGANIZATION として検出される。NER が一般語を社名と
取り違えているもので、フィラーの問題とは別。実在の会社を指していないので
マスクされても漏洩ではなく過剰マスク（品質の問題）。一般語の除外リストを
持つかどうかは、マスク対象の方針そのものなので別途決める。

`eval.jsonl` の NEGATIVE には `えっと` だけを載せてある。`弊社` を載せると
「今の挙動は誤り」と宣言することになり、方針を決める前に門を立ててしまうため。

## 内容

すべて架空。実在の組織・人物とは関係がない。会社名も個人名も含んでいない。
