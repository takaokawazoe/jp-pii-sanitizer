# number_formats.txt の正解

## 何のためのサンプルか

README は「メール／電話／郵便番号は**常時自動で**マスクする」と宣言している。その約束が
書き方の違いで破れていないかを見る。

外部レビューの指摘で発覚した。元の正規表現は

    phone  = (?<![\d\-])(?:0\d{1,4}-\d{1,4}-\d{3,4}|0\d{9,10})(?![\d\-])
    postal = (?<![\d\-])\d{3}-\d{4}(?![\d\-])

で、全角表記も括弧区切りも空白区切りも国番号も素通りしていた。日本語の業務文書で
全角数字は普通に出る。

## 切り分け（実測）

PCRE2 は `PCRE2_UTF | PCRE2_UCP` で動かしているので **`\d` は全角数字にも当たる**。
つまり数字クラスは元から問題なかった。詰まっていたのは**リテラル**だけ:

| 入力 | 結果（修正前） | 理由 |
|---|---|---|
| `１５０-０００１` | マスクされた | `\d` が全角に当たり、区切りは ASCII |
| `０３-１２３４-５６７８` | 素通り | 先頭の `0` が `０` に当たらない |
| `150－0001` | 素通り | 区切り `-` が `－` に当たらない |

## 正解

検出対象（すべて同じ番号の書き方違い）:

    03-1234-5678 / ０３－１２３４－５６７８ / 03(1234)5678
    03 1234 5678 / +81-3-1234-5678 / 0312345678
    150-0001 / １５０－０００１

NEGATIVE（番号の形が違うのでマスクしてはいけない）:

    A-1234-5678   社員番号。先頭が数字でない
    9876-5432     4桁-4桁。郵便番号（3桁-4桁）ではない

## 既知の過剰マスク

空白区切りを許した副作用で、`0123 4567 8901` のような 12 桁の数字コードも電話として
拾う。README が宣言している範囲なので、取りこぼす側には倒さない。

## 定義の置き場所

`cpp/src/num_patterns.hpp` が唯一の定義。以前はソース 5 箇所と `models/patterns.json` に
散っていた。**patterns.json は読んでいない**——あのファイルはモデル束に同梱して配布して
おり、CI の `fetch_assets.sh` が `unzip -o` で上書きするため、直しても束を再アップロード
するまで古い定義に戻る。「手元では直っているが CI では直っていない」を作らないため。

## 内容

すべて架空。実在の電話番号・住所とは関係がない。
