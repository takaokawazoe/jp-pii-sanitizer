# Design philosophy / 設計思想

**Language:** English (below) · [日本語](#日本語)

This document records the *thinking* behind the tool — the principles that shape
how it behaves and why. It is intentionally not about implementation details
(those live in the code comments and in [cpp/README.md](cpp/README.md)); it is
about the design decisions that should survive any rewrite.

---

## English

### The problem

People increasingly want to run office documents through an external AI —
summarize a report, draft a reply, analyze a spreadsheet. But those documents
carry personal information, and sending it to an outside service is a leak. This
tool sits between the user and the AI: it removes the PII first, and puts the
real values back into the AI's answer afterward.

Because the whole point is *not leaking*, the tool runs entirely on the local
machine. Nothing is uploaded, nothing is phoned home. A privacy tool that itself
sends data anywhere has failed at its one job.

### 1. Safe by default (opt-out, not opt-in)

The risk is asymmetric: masking something that didn't need masking costs almost
nothing, but *missing* one real name can be a serious leak. So the default is to
mask **everything the detector finds**, and the operator only *removes* the few
false positives. The question is never "should I mask this?" but "is it safe to
*un*-mask this?". When in doubt, it stays masked.

This also removes a whole class of decisions. If the detector grabs
"営業部 田中一郎" as one organization, it gets masked either way — there is no need
to adjudicate person-vs-organization.

### 2. The human is the final authority

The tool does not claim to catch everything, and it is not designed to be trusted
blindly. It makes the *safe* choice the *easy* choice, and then asks a person to
confirm before anything is sent. A **safety gate** re-scans the output as a last
line of defense and refuses to call it clean if a raw value survived — but even
that is a backstop, not a guarantee. The operator is accountable for the result;
the tool's job is to make that responsibility easy to discharge well.

### 3. The preview is the truth

What the operator sees highlighted must be exactly what will be masked — no more,
no less. So the preview is generated by the **same matcher** that does the
masking, not by a separate "probably close enough" path. Before-color and
after-replacement can never disagree, including awkward cases like a company name
split across a line break or a name written in kana. If the preview and the
result could drift apart, the operator could not trust either.

### 4. Reversible when you need it — and the key stays yours

Often you want the AI's answer to come back with the real names in place. So
masking can be **reversible**: each value maps to a stable placeholder, and a
mapping table restores it later. That mapping is the most sensitive artifact in
the whole flow — it is the one thing that must **never** be sent to the AI. It
stays with the operator, and the tool treats it as such.

When reversibility isn't needed, masking is **irreversible** redaction with no
mapping kept — less to protect, less to leak.

### 5. Recall over precision

In an opt-out design the costs are lopsided, so detection is tuned to *find too
much rather than too little*. It is better to surface a borderline candidate the
operator can dismiss than to silently miss a real one. Detection favors the most
robust signal for the hardest cases (rare and obfuscated Japanese names) rather
than stacking many detectors for marginal gains — simpler is easier to trust and
to keep correct.

### 6. A clear scope boundary

The tool targets **named-entity PII**: people, organizations, addresses, and
contact details. It deliberately does **not** try to catch **structured
identifiers** — account numbers, employee IDs, dates of birth, card numbers.
Those need different, format-specific handling and a different notion of
correctness; pretending to cover them would give false confidence. Drawing the
line explicitly is part of the design, not a gap in it.

### 7. Trust comes from locality and openness

For a tool whose value *is* trust, the strongest guarantees are structural: it
runs offline (so data cannot leak), it is open source (so anyone can read what it
does), and its behavior is checked against a reference so results are
reproducible. Those properties matter more than any single detection number.

## 日本語

本ドキュメントは、ツールの*考え方*——挙動を形づくる原則と、その理由——を記録します。実装の
細部はあえて扱いません（それらはコードのコメントと [cpp/README.md](cpp/README.md) にあります）。
ここに残すのは、書き直しても生き残るべき設計判断です。

### 問題

オフィス文書を外部の AI にかけたい場面が増えています——報告書を要約する、返信を下書きする、
表を分析する。しかし文書には個人情報が含まれ、外部サービスに送ればそれは漏えいです。本ツールは
利用者と AI の間に立ち、先に PII を除去し、AI の返答に実名を戻します。

目的が*漏らさないこと*である以上、ツールは完全にローカルで動きます。何もアップロードせず、
どこにも通信しません。自身がデータを送るプライバシーツールは、唯一の仕事に失敗しています。

### 1. 既定で安全（opt-in ではなく opt-out）

リスクは非対称です。マスク不要なものをマスクしてもコストはほぼゼロですが、実名を1つ*取りこぼす*
と重大な漏えいになり得ます。だから既定は**検出したものをすべてマスク**し、操作者は少数の誤検出を
*外す*だけ。問いは常に「これをマスクすべきか？」ではなく「これを*非*マスクにして安全か？」です。
迷ったら残す。

これは判断の一群も消します。「営業部 田中一郎」を1つの組織として拾っても、どちらにせよマスク
されるので、人名か組織かを裁定する必要がありません。

### 2. 人が最終権限を持つ

ツールはすべてを捕捉するとは主張せず、盲信される設計でもありません。*安全な*選択を*簡単な*選択に
し、送信前に人の確認を求めます。**安全ゲート**が最後の防衛線として出力を再走査し、生の値が残って
いれば「クリーン」と認めません——ただしそれも保険であって保証ではありません。結果の責任は操作者に
あり、ツールの仕事はその責任を全うしやすくすることです。

### 3. プレビューが真実

操作者にハイライトで見えるものが、実際にマスクされるものと過不足なく一致しなければなりません。
だからプレビューはマスクと**同じマッチャ**で生成し、「たぶん近い」別経路では作りません。色（前）と
置換（後）は、社名が行またぎで割れる／名前がカナで書かれる等の厄介な場合も含めて、決して食い違い
ません。もしプレビューと結果がずれ得るなら、操作者はどちらも信用できません。

### 4. 必要なときは可逆に——鍵は手元に

AI の返答に実名を戻したい場面は多い。だからマスクは**可逆**にできます。各値は安定したプレース
ホルダに対応づき、対応表で後から復元します。この対応表はフロー全体で最も機微な成果物であり、
**絶対に**AI に送ってはならない唯一のものです。それは操作者の手元に留まり、ツールもそう扱います。

可逆性が不要なら、対応表を持たない**不可逆**の墨消しにします——守るものが減れば、漏れるものも減る。

### 5. 精度より再現率

opt-out 設計ではコストが偏るので、検知は*少なく取るより多く取る*方に振ります。実名を静かに
取りこぼすより、操作者が外せる境界的な候補を出す方が良い。検知は、限界的な上積みのために多数の
検出器を積むのではなく、最難関（難読な日本語名）に対して最も頑健な信号を優先します——単純な方が
信用しやすく、正しく保ちやすい。

### 6. 明確なスコープ境界

ツールが対象とするのは**名前付きエンティティの PII**——人・組織・住所・連絡先です。**構造的な
識別子**——口座番号・社員番号・生年月日・カード番号——は意図的に**扱いません**。それらは異なる
形式依存の処理と、異なる「正しさ」の概念を要し、扱うふりをすれば誤った安心を与えます。境界を
明示することは、設計の欠落ではなく設計の一部です。

### 7. 信頼はローカル性と公開性から来る

価値そのものが信頼であるツールにとって、最も強い保証は構造的なものです。オフラインで動く（だから
データは漏れない）、オープンソースである（だから誰でも挙動を読める）、参照実装と突き合わせて検証
されている（だから結果が再現できる）。これらの性質は、単一の検出スコアより重要です。
